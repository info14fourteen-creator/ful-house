# Platform Targets

Дата: 2026-07-05

Платформа должна проектироваться как один продукт с несколькими поверхностями, а не как отдельные несвязанные приложения.

## 1. Desktop web

Основная рабочая поверхность для обучения, анализа и игры.

Требования:

- широкий покерный стол без тесноты;
- видимые AI-соперники, банк, стек, board, hand history;
- удобная панель диагностики и разборов;
- статьи, RSS, турниры и личный план доступны из навигации;
- дизайн темный, плотный, но читаемый.

## 2. Mobile web

Обязательная версия, не упрощенный остаток desktop.

Требования:

- стол адаптирован под вертикальный экран;
- действия игрока доступны большим пальцем;
- карты, стек, pot и CTA не перекрываются;
- навигация компактная;
- статьи и новости читаются без горизонтального скролла;
- диагностика должна проходиться за короткие сессии.

## 3. Telegram Mini App

Легкий вход для аудитории из Telegram.

Назначение:

- быстрая диагностика уровня;
- короткие тренировочные раздачи;
- daily hand challenge;
- уведомления о следующем уроке;
- быстрый доступ к статьям и турнирам.

Ограничения:

- не перегружать интерфейс;
- минимум тяжелых экранов;
- Telegram WebApp SDK только после выбора технологического стека;
- никакого real-money функционала.

## 4. macOS app

Отдельная desktop-программа в духе утилитарного рабочего приложения вроде Tronix Rent: окно, состояние, локальная история, быстрый запуск тренировок.

Назначение:

- тренировки и разборы без браузерного шума;
- локальная история сессий;
- быстрый доступ к AI-столу и личному плану;
- позже: синхронизация с web-аккаунтом.

Возможные подходы:

- Tauri/Electron wrapper вокруг web-приложения для раннего MVP;
- нативное SwiftUI-приложение после стабилизации API и UX;
- общий backend/API для web, Telegram Mini App и macOS.

## Общий продуктовый контракт

Все поверхности должны использовать одну и ту же логику:

- единые уровни игрока 0-6;
- единые метрики диагностики;
- единые AI-агенты;
- единый формат hand history;
- единый safety-контур;
- единый контентный источник для статей, RSS и турниров.

## Проверка после каждого шага

После каждого инкремента надо фиксировать:

- Planned: какой шаг выполнялся.
- Done: что реально сделано.
- Files changed: какие файлы изменились.
- Desktop impact: что меняется для desktop.
- Mobile impact: что меняется для mobile.
- Telegram Mini App impact: влияет ли на mini app.
- macOS impact: влияет ли на будущий macOS app.
- Verification: как проверено.
- Remaining: что осталось или что переносится дальше.
- Blockers: что мешает.
