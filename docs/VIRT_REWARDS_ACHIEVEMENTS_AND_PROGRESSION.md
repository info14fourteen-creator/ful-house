# FUL.HOUSE — VIRT Rewards, Achievements & Progression

## Core thesis

VIRT should reward users for making their House more real, useful, structured and alive. It must not become a click-farming currency.

**FUL rewards progress, not clicks.**

The system therefore rewards meaningful state changes, verified contributions, sustained useful maintenance and achievements rather than raw interaction volume.

---

## Reward classes

### Discovery Rewards
One-time rewards for opening a meaningful part of the House.

Examples:
- Connect first professional source
- Unlock Kitchen
- Create first real pet
- Add first vehicle
- Create first Travel Memory
- Create first Sports Corner
- Add first private Vault document

Discovery rewards are generally one-time per capability/category.

### Contribution Rewards
Rewards for adding durable useful data or content.

Examples:
- Digitize a real pet
- Add vehicle service history
- Save and normalize a real recipe
- Add meaningful wardrobe inventory
- Confirm a restaurant visit
- Add a real House appliance with model/manual
- Add a verified personal document to encrypted Vault

Repeated actions use cooldowns, diminishing rewards and/or milestone thresholds.

### Maintenance Rewards
Small rewards for useful updates that keep the digital twin current.

Examples:
- Update weight after a reasonable interval
- Update vehicle mileage
- Confirm completed maintenance
- Update pet appearance after meaningful aging
- Refresh real-home appliance/service data

Maintenance rewards require domain-specific minimum intervals or meaningful deltas. Updating weight 100 times in one afternoon is one state change, not an economic career.

### Achievement Rewards
Large rewards for meaningful milestones.

Examples:
- First 5K
- 100 workouts
- Cooked recipes from 10 countries
- 25 recipes actually cooked
- Completed vehicle maintenance profile
- Built first creator collection
- Completed first structured Travel Memory

Achievements can also unlock non-purchasable House Objects.

### Creator Rewards
Earned through approved marketplace creation, sales, remix royalties and high-quality community contributions.

---

## Reward event model

Every rewardable event should produce a deterministic record:

- event type
- owner/House
- source/provenance
- timestamp
- reward rule version
- verification level
- resulting VIRT amount
- reason
- anti-abuse signals

LLMs may suggest achievements or classify context, but they do not mint VIRT directly.

A deterministic Reward Engine validates the rule and issues the reward.

---

## Verification levels

Not all activity is equally trustworthy.

Suggested levels:

1. Manual claim
2. User-confirmed imported data
3. Connected-service evidence
4. Device/sensor evidence
5. Multi-source corroboration

Reward rules can require different evidence levels. High-value achievements should require stronger evidence than cosmetic onboarding rewards.

The system should avoid creating a surveillance incentive merely to increase reward confidence. Users can choose privacy over maximum rewards.

---

## Anti-farming principles

- No reward for generic daily login.
- No unlimited reward for repeating the same field update.
- Cooldowns for maintenance events.
- Diminishing returns for repetitive low-value contributions.
- Category caps where appropriate.
- Duplicate detection.
- Connected-source provenance where useful.
- Suspicious event review for high-value rewards.
- Explicit corrections can update data without necessarily creating another reward.
- AI cannot independently approve its own suggested reward.

---

## Earned VIRT vs Purchased VIRT

The ledger should retain provenance even if both balances can be spent similarly.

### Earned VIRT
Generated by validated activity, achievements, creation and contribution.

### Purchased VIRT
Acquired through permitted purchase mechanisms if/when introduced.

Some status items or achievements may require Earned VIRT or direct achievement completion and cannot simply be purchased.

This preserves visible status for lived contribution rather than pure spending.

---

## Room progression

Each major room can have its own progression model.

Progress should combine meaningful completeness, real activity and achievements, not raw click counts.

Example Kitchen:
- Level 1: Kitchen created + first recipes
- Level 2: meaningful recipe library + cooked feedback
- Level 3: taste profile + repeated cooking history

Garage:
- Level 1: real vehicle digitized
- Level 2: maintenance history established
- Level 3: active maintenance profile and useful records

Wardrobe:
- Level 1: initial real inventory
- Level 2: useful wardrobe coverage
- Level 3: outfit/use history and care data

Sports:
- Level 1: fitness profile
- Level 2: real training history or tracker connection
- Level 3: sustained verified activity and adaptive plan

Room level rewards can include:
- VIRT
- visual room evolution
- new Butler capabilities
- earned-only objects
- creator tools
- deeper analytics

---

## House progression

Avoid a simplistic profile-completion percentage. Internally the system may calculate completeness, but user-facing language should emphasize how alive/useful the House has become.

Possible concept:

**House Vitality**

Signals can include:
- identity sources
- useful rooms
- current data
- real objects
- memories
- contributions
- creator activity
- relationships/shared memories

The Butler can identify underdeveloped areas without coercive gamification.

Example:

> Your Library has almost no personal history yet. Connect a reading source or add books manually and I can organize it.

---

## Earned objects

Achievements should often produce physical evidence in the House.

Examples:
- First 5K → medal
- 100 workouts → trophy
- World Kitchen → world-map kitchen object
- Traveler milestone → globe/souvenir
- Reading milestone → special shelf
- Creator milestone → studio object

Earned objects are marked distinctly from purchased assets and preserve achievement provenance.

---

## Sources and sinks

VIRT supply requires explicit economic controls.

### Sources
- Discovery rewards
- Validated contributions
- Maintenance milestones
- Achievements
- Creator sales
- Remix royalties
- Community contributions
- Limited campaigns if later introduced

### Sinks
- UGC furniture/assets
- House expansion
- Architecture/surfaces
- Digital pets/accessories
- Butler cosmetics/uniform variants
- Creator tools
- AI premium compute/tasks where appropriate
- Services/products from other users
- Special personalization

The economy must be simulated before fixed emission rates are launched.

---

## Marketplace settlement direction

A marketplace purchase may eventually split VIRT among creator, platform treasury and burn/removal mechanisms. Exact percentages are deliberately not fixed in this specification and require economic simulation.

The ledger must support transparent settlement components and versioned rules.

## Reward examples

- Connect LinkedIn → one-time Discovery Reward
- Connect Spotify/music provider → one-time Discovery Reward
- Digitize real pet → Discovery/Contribution Reward
- Add first encrypted document → Discovery Reward; do not reward endlessly per sensitive document
- Create Kitchen → Discovery Reward
- Save meaningful first recipe → Contribution Reward
- Cook recipe and confirm outcome → Activity/achievement progress
- Add height/weight → initial profile reward
- Update weight after valid interval → small Maintenance Reward
- Add real car → Contribution Reward
- Add verified service event → Maintenance/Contribution Reward
- Create Sports Corner → Discovery Reward
- Complete training milestone → Achievement Reward

---

## Privacy principle

VIRT must never pressure users into exposing private information publicly.

A private encrypted document can satisfy a Vault completeness/reward rule without FUL.HOUSE learning its plaintext server-side.

Public sharing is not required to receive private-life progression rewards.

---

## Core loop

**Live → Connect → Build → Earn → Improve → Create → Sell → Explore → Live more**

VIRT exists to make useful participation compound into a richer House and richer ecosystem.
